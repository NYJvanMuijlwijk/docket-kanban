# Impeccable Audit Report: Collaborative Kanban Board

**Date:** 2026-03-28
**Branch:** slice-5/design-polish
**Auditor:** Claude Code (impeccable:audit)

---

## Anti-Patterns Verdict

**PASS.** This does *not* look AI-generated. No cyan-on-dark palette, no gradient text, no glassmorphism, no bounce/elastic easing, no nested cards, no hero metric layouts, no generic card grids. The aesthetic is intentionally muted blueGrey Material 3 with opacity-based depth — exactly matching the stated design direction (Linear/Vercel/Raycast references). Widget decomposition is disciplined: zero functions returning `Widget`, all extracted to private widget classes. Button hierarchy is clean (TextButton secondary, FilledButton primary). Empty states use a centralized `StatusContent` component with contextual icons and actions.

## Detailed Findings by Severity

### Critical Issues

#### C1. Drag-and-drop is not keyboard accessible
- **Location:** `lib/features/board/presentation/board_detail_screen.drag.dart`, entire drag system
- **Category:** Accessibility
- **Description:** The kanban board's core interaction (moving cards between columns) relies entirely on pointer-based `Draggable`/`DragTarget`. No keyboard alternative exists — no arrow-key movement, no context menu "Move to column", nothing.
- **Impact:** Users who rely on keyboard navigation (motor impairments, power users) cannot use the primary feature.
- **WCAG:** 2.1.1 Keyboard (Level A) — all functionality must be operable via keyboard
- **Recommendation:** Add a "Move card" action in the card's popup menu or long-press sheet that lets users pick a target column and position.
- **Suggested command:** `/harden`

#### C2. No Semantics widgets in the entire codebase
- **Location:** Project-wide (0 `Semantics` widgets, 0 `semanticLabel` parameters)
- **Category:** Accessibility
- **Description:** Interactive elements (GestureDetector, Dismissible, drag handles, icon buttons) lack semantic descriptions. Only 3 tooltips exist in the entire project (`card_form_sheet.dart:257,262`, `column_management_sheet.dart:420`).
- **Impact:** Screen reader users cannot understand what interactive elements do. The board is effectively unusable with TalkBack/VoiceOver.
- **WCAG:** 1.1.1 Non-text Content (Level A), 4.1.2 Name/Role/Value (Level A)
- **Recommendation:** Add `Semantics` wrappers to all interactive elements. Add `semanticLabel` to Icon widgets used as content (not decoration).
- **Suggested command:** `/harden`

### High-Severity Issues

#### H1. Timer.periodic forces full-screen rebuild every 60 seconds
- **Location:** `lib/features/board/presentation/board_list_screen.dart:27-30`
- **Category:** Performance
- **Description:** A `Timer.periodic` calls `setState()` every 60 seconds to refresh relative timestamps ("2 min ago"). This rebuilds the entire board list screen, including all `Dismissible` wrappers and `ListTile` widgets.
- **Impact:** Unnecessary frame work every 60s. On low-end devices or large board lists, this causes a visible jank spike.
- **Recommendation:** Replace with a targeted `ValueNotifier` or `StreamBuilder` that only rebuilds the timestamp text widgets, not the entire screen.
- **Suggested command:** `/optimize`

#### H2. Card/column providers sort on every stream emission
- **Location:** `lib/features/board/presentation/providers/card_providers.dart:13-15`, `column_providers.dart:13-15`
- **Category:** Performance
- **Description:** `watchCards()` and `watchColumns()` streams `.map()` a sort on every emission — even when the data hasn't changed or the order is identical.
- **Impact:** Downstream `ref.watch()` consumers rebuild on every emission because `.sort()` mutates the list in-place (no equality check). With many cards, sorting per-emission adds up.
- **Recommendation:** Use `distinctUntilChanged` with a list equality check, or cache the sorted result with a `listEquals` guard.
- **Suggested command:** `/optimize`

#### H3. Icon buttons lack semantic labels
- **Location:** Column popup menus (`board_detail_screen.column.dart:349`), card edit/delete (`card_form_sheet.dart:257,262`), drag handle (`column_management_sheet.dart:314`), add column (`column_management_sheet.dart:420`)
- **Category:** Accessibility
- **Description:** Icon-only interactive elements rely on visual recognition. Three have tooltips; the rest have nothing for assistive technology.
- **Impact:** Screen reader users hear "button" with no description of what the button does.
- **WCAG:** 4.1.2 Name/Role/Value (Level A)
- **Recommendation:** Add `tooltip` to all `IconButton` widgets (Flutter reads tooltip as semantic label). Add `Semantics(label:)` to `GestureDetector` wrappers.
- **Suggested command:** `/harden`

#### H4. Card title text has no overflow handling
- **Location:** `board_detail_screen.card.dart:84`, `card_form_sheet.dart:250`
- **Category:** Responsive
- **Description:** `Text(card.title)` renders without `maxLines` or `overflow`. Long card titles wrap unbounded, potentially distorting card height and column layout.
- **Impact:** A single long title can push a column's card list out of proportion, breaking visual rhythm. Worse at larger text scaling.
- **Recommendation:** Add `maxLines: 2, overflow: TextOverflow.ellipsis` to card title in list view. Detail view can remain unwrapped.
- **Suggested command:** `/harden`

#### H5. ReorderableListView in column manager has no keyboard accessibility announcement
- **Location:** `lib/features/board/presentation/widgets/column_management_sheet.dart:162-216`
- **Category:** Accessibility
- **Description:** The `ReorderableListView` for column ordering uses drag handles. While Flutter's `ReorderableListView` has basic keyboard support via long-press activation, there are no semantic announcements for reorder state.
- **Impact:** Keyboard users may not discover they can reorder, and screen reader users get no feedback during the operation.
- **WCAG:** 2.1.1 Keyboard (Level A)
- **Suggested command:** `/harden`

### Medium-Severity Issues

#### M1. AnimatedContainer wraps entire card list during hover
- **Location:** `board_detail_screen.column.dart:171-202`
- **Category:** Performance
- **Description:** The column hover highlight uses `AnimatedContainer` wrapping both the decoration and the full `_CardListView` child tree. During the 200ms color transition, the entire card list subtree is re-evaluated.
- **Recommendation:** Isolate the animated decoration from children, or wrap in `RepaintBoundary`.
- **Suggested command:** `/optimize`

#### M2. Multiple independent ShimmerScope instances
- **Location:** `board_detail_screen.dart:281,303`, `column_management_sheet.dart:434`
- **Category:** Performance
- **Description:** Each `ShimmerScope` creates its own `AnimationController`. Multiple visible skeletons animate out of sync.
- **Recommendation:** Use a single `ShimmerScope` ancestor or synchronize controllers.
- **Suggested command:** `/optimize`

#### M3. Ghost card at 0.4 opacity reduces text contrast
- **Location:** `board_detail_screen.drag.dart:149`
- **Category:** Accessibility
- **Description:** During drag, the source card's ghost is rendered at 40% opacity. Text within becomes difficult to read, especially for low-vision users.
- **Recommendation:** Increase to 0.5-0.6, or use a color tint instead of opacity.
- **Suggested command:** `/polish`

#### M4. ListView.builder without itemExtent
- **Location:** `board_list_screen.dart:105-146`
- **Category:** Performance
- **Description:** Board list `ListView.builder` lacks `itemExtent` or `prototypeItem`, forcing Flutter to measure each item during scroll.
- **Recommendation:** Add `itemExtent` for consistent `ListTile` heights.
- **Suggested command:** `/optimize`

#### M5. No mobile/tablet breakpoints beyond max-width constraints
- **Location:** `lib/core/responsive.dart`
- **Category:** Responsive
- **Description:** Only `kContentMaxWidth`, `kColumnMinWidth`, `kColumnMaxWidth`, `kSheetMaxWidth` are defined. No explicit breakpoints for small phones (<360px), tablets, or landscape.
- **Recommendation:** Define device-class breakpoints for future adaptive layouts.
- **Suggested command:** `/adapt`

#### M6. Auto-scroll parameters are not viewport-relative
- **Location:** `auto_scroll_handler.dart:16-18`
- **Category:** Responsive
- **Description:** `edgeZone = 40.0`, `minSpeed = 50.0`, `maxSpeed = 600.0` are hardcoded. On small phones, 40px edge zone is proportionally large; on tablets, it's too small.
- **Recommendation:** Scale edge zone as a percentage of viewport width.
- **Suggested command:** `/adapt`

#### M7. GestureDetector for column rename lacks Semantics
- **Location:** `column_management_sheet.dart:340`
- **Category:** Accessibility
- **Description:** Column name tap-to-edit uses bare `GestureDetector` without semantic label. Screen readers announce nothing about the interaction.
- **Suggested command:** `/harden`

## Patterns & Systemic Issues

1. **Accessibility is systematically absent.** Zero `Semantics` widgets, minimal `tooltip` usage, no keyboard alternatives for drag interactions. This is the single biggest gap — it's not a few missing labels, it's a project-wide blind spot.

2. **Performance patterns are generally good** but the provider sort-on-every-emission pattern (`card_providers.dart`, `column_providers.dart`) is a systemic issue that will scale poorly with card count.

3. **Responsive design has a solid foundation** (LayoutBuilder, fluid column widths, granular MediaQuery) but lacks device-class breakpoints for adaptive behavior.

---

## Positive Findings

1. **Zero hardcoded colors** — entire project uses `Theme.of(context).colorScheme`. Theme switching would work immediately.
2. **Excellent widget decomposition** — no functions returning `Widget`, all private widget classes with proper lifecycles.
3. **Clean button hierarchy** — TextButton/FilledButton pairing is consistent across all dialogs.
4. **Centralized empty states** — `StatusContent` component with icons and actions, reused everywhere.
5. **No anti-pattern "AI slop"** — no glassmorphism, no gradient text, no bounce easing, no nested cards, no centered-everything.
6. **Modern MediaQuery usage** — all granular APIs (`.viewInsetsOf()`, `.paddingOf()`, `.sizeOf()`).
7. **Proper animation curves** — `Curves.easeInOut` throughout, appropriate durations (200-300ms for UI, 1500ms for shimmer).
8. **Good overflow handling** — most text has `maxLines` + `TextOverflow.ellipsis`, Rows use `Expanded`.

## Recommendations by Priority

### 1. Immediate (Critical blockers)
- Add keyboard alternative for card movement (context menu or bottom sheet action)
- Add `Semantics` + `semanticLabel` to all interactive elements

### 2. Short-term (This sprint)
- Replace `Timer.periodic` rebuild with targeted timestamp refresh
- Add `distinctUntilChanged` or memoization to card/column provider sorts
- Add `maxLines`/`overflow` to card title text
- Add `tooltip` to all icon-only buttons

### 3. Medium-term (Next sprint)
- Isolate `AnimatedContainer` decoration from card list children
- Synchronize shimmer animations
- Define device-class breakpoints in `responsive.dart`
- Make auto-scroll edge zone viewport-relative

### 4. Long-term (Nice-to-have)
- Add high-contrast theme option
- Add scroll position persistence
- Scale sheet padding for screen size
- Add `itemExtent` to list views
